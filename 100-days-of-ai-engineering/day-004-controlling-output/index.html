1 · The gist

At every step the model produces a probability for each possible next token. Settings like temperature, top-k and top-p decide how that list is reshaped and trimmed before one token is picked.

3 · Analogies

Temperature = how adventurous you order. Low: always your usual biryani. High: you point at random dishes on the menu.
Top-k = a fixed short menu. Only the 3 most popular dishes are offered, however many the kitchen can make.
Top-p = the menu covering 90% of orders. If everyone orders biryani, the menu is tiny. If tastes are scattered, it grows.
Reasoning model = a student showing rough work. It writes steps on the side before giving the final answer.

4 · Definitions

Logits
The raw scores the model gives every token before they become probabilities.
Temperature
A number that divides the logits. Below 1 sharpens, above 1 flattens. 0 means always pick the top token.
Greedy decoding
Always take the single most likely token (temperature 0).
Top-k
Keep only the k most likely tokens, then renormalise and sample.
Top-p (nucleus)
Keep the smallest set of top tokens whose probabilities add up to at least p.
Penalties
Frequency and presence penalties discourage repeating tokens already used.
Reasoning tokens
Hidden “thinking” tokens a reasoning model writes first. Usually billed as output tokens.

7 · The “why?” ladder

Why does dividing by temperature change randomness?
Dividing shrinks the gaps between scores when T is above 1 and stretches them when T is below 1. Softmax then turns small gaps into flat odds and big gaps into a clear winner.
Why not always use temperature 0?
It gives the most predictable output but can be dull and repetitive, and it still doesn’t guarantee identical results every run. For creative or varied tasks you want some randomness.
Why top-p instead of top-k?
k is fixed whether the model is sure or confused. p adapts: few tokens survive when the model is confident, many when it isn’t.
Why does thinking first help?
Every token written becomes input for the next one (Day 1’s loop). Writing intermediate steps gives the model a scratchpad and more computation before it commits to an answer.
Why do reasoning models cost more?
The hidden thinking tokens are generated one by one and usually billed as output tokens, so you pay for them and wait for them.
Pitfalls: lowering temperature to “fix hallucinations” (it only makes the same wrong answer consistent) · changing temperature and top-p together · using a reasoning model for a simple lookup.

10 · Coding question: build the sampler’s probabilities

Medium · 25 min · skills: lists, sorting, sets, math. Attempt it first, then the hint, then the solution.

Task. Write sample_probs(logits, temperature, top_k=None, top_p=None) that returns the final probability for each token (same order as logits), with no randomness. Steps: 1) if temperature == 0, return a one-hot list on the highest logit. 2) divide logits by temperature and apply softmax. 3) if top_k is set, keep only the k most likely. 4) if top_p is set, keep the smallest top set whose probabilities add up to at least p (measured on the step-2 probabilities). 5) set removed tokens to 0 and renormalise the rest so they sum to 1.
logits = [2.0, 1.0, 0.0]

sample_probs(logits, 1.0)             # [0.665, 0.245, 0.090]
sample_probs(logits, 1.0, top_k=2)    # [0.731, 0.269, 0.0]
sample_probs(logits, 1.0, top_p=0.6)  # [1.0, 0.0, 0.0]  (first token alone already covers 0.665)
sample_probs(logits, 0.5)             # [0.867, 0.117, 0.016]  (sharper)
sample_probs(logits, 0)               # [1.0, 0.0, 0.0]
💡 Hint (open only after trying)Get order = sorted(range(n), key=lambda i: probs[i], reverse=True). Keep a set of indices to keep: start with everything, intersect with order[:top_k], then walk order adding probabilities until the running total reaches top_p and intersect with that set. Finally divide each kept probability by the kept total.
✅ Solution + explanation (open after your attempt) 
import math

def sample_probs(logits, temperature, top_k=None, top_p=None):
    n = len(logits)
    if temperature == 0:
        i = logits.index(max(logits))
        return [1.0 if j == i else 0.0 for j in range(n)]
    scaled = [x / temperature for x in logits]
    m = max(scaled)
    exps = [math.exp(x - m) for x in scaled]
    total = sum(exps)
    probs = [e / total for e in exps]
    order = sorted(range(n), key=lambda i: probs[i], reverse=True)
    keep = set(order)
    if top_k is not None:
        keep &= set(order[:top_k])
    if top_p is not None:
        cum, nucleus = 0.0, set()
        for i in order:
            nucleus.add(i)
            cum += probs[i]
            if cum >= top_p:
                break
        keep &= nucleus
    kept_total = sum(probs[i] for i in keep)
    return [probs[i] / kept_total if i in keep else 0.0 for i in range(n)]
How it works
  1. Temperature 0 is a special case: dividing by zero is impossible, and the answer is simply the top token (greedy decoding).
  2. Divide by temperature, then softmax. Subtracting the max first avoids overflow without changing the result.
  3. Sort indices by probability so “top” means highest, while still remembering each token’s original position.
  4. Top-k keeps the first k indices. Top-p adds tokens from the top until the running total reaches p, including the one that crosses the line, so at least one token always survives.
  5. Intersect the two sets when both are given, then renormalise so the survivors sum to 1. Removed tokens get exactly 0 and can never be sampled.
  6. Cost: sorting makes it O(n log n) in the vocabulary size. Real libraries do the same thing by setting removed logits to minus infinity.
How does this become one token? Draw a random number and walk the probabilities until the running total passes it (the “Sample ×20” button above does exactly this).

11 · Outcome check (say it aloud)

A teammate sets temperature to 0 “so the model stops hallucinating”. What is right and wrong about that, and what would you suggest instead?

Model answerTemperature 0 makes output more predictable, so the same answer comes back each time, but it doesn’t make facts true: a wrong answer just becomes consistently wrong, and even temperature 0 isn’t a guarantee of identical runs. To reduce hallucinations, ground the model with retrieved sources (RAG), ask it to cite them, and verify outputs. Keep low temperature for tasks like extraction where you want consistency.
