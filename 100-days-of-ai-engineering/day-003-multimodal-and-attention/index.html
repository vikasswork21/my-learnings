3 · Analogies

Q, K, V = library. Query is what you ask the librarian. Key is the label on each book’s spine. Value is what’s inside the book. You match your question to the labels, then read mostly the best-matching books and blend what they say.
Attention = WhatsApp group. In “The cat sat on the mat because it was tired”, the word “it” scans every message and pays most attention to “cat”.

4 · Definitions

Modality
A type of input: text, image, audio, video.
Patch
A small square tile of an image. Each patch becomes one token.
Attention
Each token gathers information from the other tokens, weighted by relevance.
Query / Key / Value
Three vectors per token: what it looks for, how it can be found, what it hands over.
Attention weights
Probabilities (summing to 1) saying how much a token listens to each other token.
Multi-head
Several attentions in parallel, each free to focus on a different relationship.

6 · The “why?” ladder

Why can one model handle images and audio?
Everything is sliced into pieces and turned into numbers in a shared space. The layers don’t care where a token came from.
Why do we need attention at all?
Meaning depends on context. “It” must look at “cat” to mean anything. Attention lets each token pull in the relevant information from the others.
Why split into Query, Key and Value?
Different jobs. Query says what I need, Key says how I can be found, Value is the information handed over. Matching uses Q and K; the content comes from V.
Why divide the scores by √d?
Dot products grow with vector size. Without scaling, softmax saturates into near 0 or 1 and learning becomes hard. Scaling keeps it smooth.
Why do images cost so many tokens?
An image is a grid of patches and each patch is a token. Double the width and height and you get 4× the tokens; attention pairs grow with tokens².
Pitfalls: assuming a model “sees” like a human (it works on patch tokens and can miss small text or exact counts) · treating attention weights as a full explanation of why it answered.

9 · Coding question: attention in pure Python

Medium · 20–25 min · skills: lists, comprehensions, math. Attempt it first, then the hint, then the solution.

Task. Write softmax(xs) that turns a list of scores into probabilities that sum to 1. Then write attention(q, K, V) for one query: score each key as dot(q, k) / sqrt(len(q)), apply softmax, and return the weighted sum of the value rows.
q = [1, 0]
K = [[1, 0], [0, 1], [1, 1]]
V = [[10, 0], [0, 10], [5, 5]]

# scores = [1, 0, 1] / sqrt(2) = [0.707, 0, 0.707]
# weights = softmax(scores) = [0.401, 0.198, 0.401]
attention(q, K, V)   # [6.017, 3.983]

softmax([0, 0])      # [0.5, 0.5]
💡 Hint (open only after trying)Dot product: sum(a * b for a, b in zip(q, k)). For softmax, compute math.exp(x) for each score and divide by the total. The output’s j-th number is sum(w[i] * V[i][j]) over all rows i.
✅ Solution + explanation (open after your attempt) 
import math

def softmax(xs):
    m = max(xs)
    exps = [math.exp(x - m) for x in xs]
    total = sum(exps)
    return [e / total for e in exps]

def attention(q, K, V):
    d = len(q)
    scores = [sum(a * b for a, b in zip(q, k)) / math.sqrt(d) for k in K]
    w = softmax(scores)
    return [sum(w[i] * V[i][j] for i in range(len(V))) for j in range(len(V[0]))]
How it works
  1. Dot product measures how similar the Query is to each Key. Bigger means a better match.
  2. Divide by √d keeps scores from growing with vector size, so softmax doesn’t saturate.
  3. softmax turns scores into weights that sum to 1. Subtracting the max first avoids overflow in exp and doesn’t change the result.
  4. Weighted sum of Values: keys that match get more say, so the output leans toward their values. Here keys 1 and 3 match best, so the output sits between [10,0] and [5,5].
  5. Cost: one query costs O(n·d) for n keys. Every token is a query, so all tokens cost O(n²·d). This is why long inputs and big images get slow and costly (Day 2).
What do real models add? Learned matrices that create Q, K and V from each token, many heads in parallel, and batch matrix maths instead of Python loops.
