3 · Analogy

The chai-stall friend. Imagine a friend who has overheard billions of conversations. You say “Hyderabad’s famous ___” and he instantly feels that “biryani” is very likely, “haleem” fairly likely, “bicycle” almost impossible. He doesn’t look anything up; he just completes the sentence from what he has absorbed. Then he completes the next word the same way. That is an LLM.

4 · Definitions (written once, in plain words)

Token
A chunk of text (a word, part of a word, a symbol) that the model reads and writes. Roughly ¾ of an English word.
Embedding
A list of numbers that stands for a token’s meaning. Similar meanings sit close together.
Layer
One processing stage that refines every token’s numbers using the surrounding tokens. Real models stack many.
Probabilities
A score for every token in the vocabulary (tens of thousands) saying how likely it is to come next. They sum to 100%.
Parameters (8B, 70B)
The learned numbers inside the model. 8B = 8 billion. They store what the model learned.
Autoregressive
It feeds its own output back in as input, one token at a time.

5 · What it is NOT

It looks like…But actually…
A databaseNothing is stored as rows to fetch. Each answer is generated fresh from learned numbers.
A search engineNo live web or index lookup unless you give it a tool.
A fixed programNo if/else rules. Behaviour comes from learned numbers, so the same prompt can give different answers.

6 · The “why?” ladder

Why does guessing the next word make it “know” things?
To guess well across trillions of tokens it must absorb grammar, facts and patterns of reasoning. Knowledge is a by-product of getting good at guessing.
Why is it fluent but sometimes wrong?
It is trained to produce a likely continuation, not a true one. Likely and true often overlap, but nothing checks facts. A confident tone is just a style it learned.
Why do I get different answers each time?
It samples from the probabilities instead of always taking the top one. (You control this with temperature on Day 4.)
Why do chat models follow instructions, refuse and hedge?
A raw “base” model only autocompletes (“brilliant but useless”: asked a question, it may output more questions). Extra training on instruction/answer pairs (SFT), then human feedback (RLHF), turns it into an assistant.
Why isn’t bigger always better?
More parameters can mean more capability, but also more cost and delay. For simple tasks a small model is often enough. You choose by testing (Day 6).
Pitfall: “It answered confidently, so it must be right.” Confidence is not evidence.

10 · Coding question: a tiny next-token predictor

Easy–medium · 15–20 min · skills: dict, Counter, loops. Attempt it first, then open the hint, then the solution.

Task. Write three functions that mimic an LLM in the simplest possible way (it looks only at the previous word):
build_model(text) counts, for each word, which words follow it and how often.
predict_next(model, word) returns the most frequent follower, or None if the word was never followed by anything. On a tie, return the one seen first.
generate(model, start, n) starts at start and repeatedly appends the predicted next word, up to n times, stopping early if there is no prediction. Return the words joined by spaces.
text = "the cat sat on the mat the cat ate the fish"
model = build_model(text)

predict_next(model, "the")   # "cat"   (cat x2, mat x1, fish x1)
predict_next(model, "cat")   # "sat"   (sat and ate tie; sat came first)
predict_next(model, "fish")  # None    (nothing follows "fish")
generate(model, "the", 5)    # "the cat sat on the cat"
💡 Hint (open only after trying)Pair each word with its successor using zip(words, words[1:]). A defaultdict(Counter) saves you the “is the key there yet?” code. max(..., key=...) returns the first maximum it meets.
✅ Solution + explanation (open after your attempt) 
from collections import defaultdict, Counter

def build_model(text):
    words = text.split()
    model = defaultdict(Counter)
    for cur, nxt in zip(words, words[1:]):
        model[cur][nxt] += 1
    return model

def predict_next(model, word):
    if word not in model:
        return None
    return max(model[word].items(), key=lambda kv: kv[1])[0]

def generate(model, start, n):
    out = [start]
    for _ in range(n):
        nxt = predict_next(model, out[-1])
        if nxt is None:
            break
        out.append(nxt)
    return " ".join(out)
How it works
  1. build_model pairs every word with the one after it and counts the pairs. That table is the simplest possible “probability of next word given current word”.
  2. predict_next picks the highest count: always taking the top choice is called greedy decoding (like temperature 0). max keeps the first of equal counts, which gives our “seen first” tie rule.
  3. generate feeds each output back in as the next input: that is the autoregressive loop from your flowchart. It stops on None because the model has never seen anything follow that word.
  4. Cost: building is O(n) for n words; each prediction scans the few distinct followers; generating n words is roughly O(n·k).
Why does it say “the cat sat on the cat”? It only remembers one word of context and always takes the top choice, so it drifts and can loop. A real LLM looks at thousands of tokens, learns patterns with layers of numbers instead of a count table, and samples instead of always taking the top. Try next: use random.choices(list(c), weights=c.values()) in place of max and run it five times. You have just rebuilt the “different answer each time” effect.

Model answerAn LLM turns your text into tokens and numbers, passes them through layers to get a probability for every possible next token, picks one, appends it and repeats. Because it is trained to produce a likely continuation rather than check facts, it can state wrong things in a perfectly fluent, confident tone.
